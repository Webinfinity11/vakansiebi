# JOBX QA — 2026-10-08

## Scrapers and automation

- Production cleanup retired 329 obsolete queue entries and cleared 34 reviews that new-only workers could never process. Vacancy statuses were checked before/after; no vacancies were deleted by the cleanup. A private backup is retained locally.
- Collectors use the shared three-calendar-day queue predicate. Imported records and retired source IDs are not revived. Publication dates available on jobs.ge listings retire old items without fetching their details, and known newest dates get processing priority.
- Structurally invalid new snapshots receive a terminal recorded result rather than an indefinite quality-review wait. Transient fetch errors retain bounded automatic retries.
- Cloud next-run estimates follow the actual six daytime GitHub cron slots. Government collectors use their local interval. jobs.ge has a production ceiling of 200 records / 8 minutes, with robots spacing preserved.
- Government collection is installed as a macOS LaunchAgent with a runtime outside protected Desktop folders. First verified runs imported 93 hrgov and 1 worknet vacancy without fetch failures. Collection requires this Mac to be awake and online.

## Companies

- Existing company catalogue names, aliases and fuzzy candidates were audited using active vacancies and employer branding. Generic descriptions and personal names do not create employer identities or share logos.
- Automatic identity reconciliation runs with the cloud worker, at most hourly. Similar spelling stays separate unless both an exact logo URL and an official employer domain agree. Free mail and vacancy-board domains are excluded as evidence. Manual editor decisions are preserved; decisions are auditable and reversible.
- Public headings and vacancy company labels use one display-name cleaner: legal forms, surrounding quotes and decorative colons are removed. Original source names and canonical identities remain intact.
- Directory links remain server rendered. Logo requests start near the viewport; loading placeholders keep their dimensions, artwork fades in and cards enter on scroll. Reduced-motion preferences disable the effects.

## Search and analytics

- Actual zero-result queries were compared against the current catalogue. Several were historical or filter-dependent: a zero-result event does not prove a globally broken keyword.
- Reviewed security and helper/washing aliases were added. An explicit comma-separated list of recognised occupations matches either occupation; ordinary phrases and technical skill queries retain their previous meaning.
- Verified example matches: `dacva` and `usaptxoeba`: 142; `damxmare`: 375; `mzareuli, mcxobeli`: 564. Counts change as the catalogue changes.
- CV analytics now separates action counts from stored records. At audit time 203 successful storage requests represented 15 stored CVs; a print click does not prove a PDF download. Independent CV sections no longer show misleading sequential conversion percentages.
- Failed CV saves survive reconnects and retry using the same identity. Clearing an offline CV cancels its queued save.

## External limits

Google crawling/indexing and third-party source availability cannot be guaranteed by a successful API response or a local test. Missing optional salary/address data is not invented to silence Search Console warnings. Private CV contents were not used to infer company identity. The daily smoke check samples pages; it is not a claim that every possible browser state or future source change has been tested.
