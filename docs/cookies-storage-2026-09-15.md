# ქუქიებისა და ბრაუზერული სთორიჯის აუდიტი — 2026-09-15

## შედეგი და ფარგლები

აპლიკაციის კოდში ერთადერთი დაყენებული cookie არის ადმინის აუცილებელი სესია `ertad_admin`; ჩვეულებრივი ვიზიტორისთვის აპლიკაცია cookie-ს არ ქმნის. **ამ აუცილებელი სესიისა და მომხმარებლის მიერ მოთხოვნილი შენახვის ფუნქციებისთვის ცალკე თანხმობის ბანერი საჭირო არ არის**, თუ შენახვა მართლაც ამ ფუნქციების მომსახურებით შემოიფარგლება. ეს არის გამოყენების დანიშნულებაზე დაფუძნებული შეფასება და არა მთელი საიტის უპირობო სამართლებრივი დასკვნა.

თავდაპირველი დასაბუთება „პერსონალური მონაცემები არ მუშავდება, ყველაფერი მოწყობილობაში რჩება და მესამე მხარე არ არის“ კოდს არ შეესაბამება:

- ბრაუზერში მომხმარებლის მოთხოვნით ინახება სახელი, ტელეფონი და ელფოსტა; ეს პერსონალური მონაცემებია.
- შენახული ძიების ფილტრები და დამალული ვაკანსიების ID-ები სიის API-ს გადაეცემა ფუნქციის შესასრულებლად.
- ნანახი ვაკანსია ავტომატურად აღინიშნება დეტალის გახსნისას; თითო ჩანაწერზე ცალკე „შენახვას“ მომხმარებელი არ აჭერს.
- ანალიტიკა ინახავს ძებნის თავისუფალ ტექსტს პირადი მონაცემების ამომცნობი ფილტრის გარეშე.
- კომპანიის ზოგი ლოგო ბრაუზერში პირდაპირ გარე დომენიდან/CDN-იდან იტვირთება.
- განცხადების ფორმას აქვს კონტექსტში გამოტოვებული `jobx-post-job-draft-v1` გასაღები; გაგზავნისას მისი მონაცემები სერვერზე გადადის.

შესწავლილია სამუშაო ხის კოდი, Next-ის დაყენებული cookie API და ქვემოთ აღწერილი ტესტი. production-ზე არც მოთხოვნა გაგზავნილა და არც ბაზა შეცვლილა. ჰოსტინგის/proxy-ის ლოგები და გარე სურათების პასუხების `Set-Cookie` არ გაზომილა; აპლიკაციის კოდში cookie-ს არქონა ამ გარე ქცევას ვერ ადასტურებს. პარალელური ნაკადები მუშაობენ იმავე ხეში, ამიტომ მითითებული ხაზები ამ წაკითხვის მომენტს ასახავს.

### applicant-ის გადაცემის ზუსტი ზღვარი

`writeApplicant()` აკეთებს მხოლოდ `storage.setItem()`-ს. მისი ერთადერთი UI ჩამწერი `preventDefault()`-ის შემდეგ ადგილობრივ მდგომარეობას აახლებს; `fetch`, beacon, server action ან ავტომატური ელფოსტა ამ გზაზე არ არის. ორივე მკითხველი (`QuickApply`, `useApplicant`) მონაცემებს გადასცემს `applicationBody()`-ს, რომელიც სახელს წერილში ჩასვამს და ტელეფონს/ელფოსტას ბოლოში დაამატებს; `emailDraft()` ქმნის `mailto:` URL-ს (`lib/application-contact.ts:51,68`; `app/quick-apply.tsx:82`; `app/vacancy-page.tsx:70`).

ამრიგად, **საიტის სერვერზე applicant-ის ავტომატური ატვირთვა არ ჩანს**, მაგრამ „მონაცემი მოწყობილობიდან არასოდეს გადის“ ზედმეტი დაპირებაა: ბმულზე დაჭერისას მონახაზი მომხმარებლის საფოსტო პროგრამას გადაეცემა; მისი სინქრონიზაცია/შემდგომი გაგზავნა უკვე ამ პროგრამასა და მომხმარებელზეა დამოკიდებული. საიტი წერილს თავად არ აგზავნის.
