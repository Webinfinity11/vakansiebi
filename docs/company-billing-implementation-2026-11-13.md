# კომპანიის სივრცის ანგარიშსწორება — 2026-11-13

მომხმარებლის მოთხოვნა: „და hr ზე მიყევი და კონკრეტენბს რაც აქვთ ყყველაფერი გვინდა მთავაირია სწორად და პრაქტიკულად იყოს“.

## 1. ფასიანი განთავსება

ახალ ფასიან შეკვეთაზე საჭიროა დადასტურებული კომპანია და ელფოსტა; ეს შემოწმება მოქმედებს როგორც billing POST-ში, ისე რედაქტირებიდან შეკვეთის სერვერულ გზაზე.

ვაკანსიის შექმნისას/რედაქტირებისას ანგარიშის მფლობელი ირჩევს სტანდარტულ, VIP ან პრემიუმ განთავსებას. ფასები/ვადები იმპორტირებულია `lib/billing.ts`-დან; ფასის კლიენტიდან მიწოდება არ ხდება. შექმნა იყენებს `submitJob`/`createInvoice`-ს. რედაქტირება `mutateJob`-ის სერვერის callback-ით იმავე ტრანზაქციაში ქმნის ინვოისს: შეცდომისას ვაკანსიის ცვლილებაც უკან ბრუნდება.

გამოქვეყნებულ, JOBX-ზე შექმნილ სტანდარტულ განცხადებაზე „VIP-ად აწევა“ ხსნის არჩევანს და იღებს ინვოისს. კომპანია ვერ ცვლის `placement_tier`, `placement_expires_at`, გადახდის სტატუსს ან აქტივაციის თარიღს. გააქტიურება კვლავ მხოლოდ არსებულ ადმინისტრირების `confirm-payment` + `publish` / `approvePlacement` გზას მიჰყვება. ინვოისის ელფოსტა არსებულ რიგში ხვდება; კოდი ელფოსტის ახალ გამგზავნს არ ამატებს.

ვაკანსიის სიაში ჩანს მოქმედი განთავსების ვადა, გადასახდელი ინვოისის ბმული ან გადახდის შემდეგ დადასტურების მოლოდინი. კითხვარისთვის რედაქტორის განაცხადების სექციის შემდეგ ჩასასმელი ადგილი დატოვებულია; თავად კითხვარი სხვა ნაკადის საქმეა.

არსებული ბილინგი ერთ ვაკანსიაზე მხოლოდ ერთ ინვოისს უშვებს (`job_invoices.job_id UNIQUE`). გაცემული ინვოისის თანხა, მიმღების რეკვიზიტები, მომსახურება და ვადა არ იცვლება. მეორე შეკვეთა, განთავსების საფეხურის შეცვლა და ავტომატური განახლება არ დამატებულა; UI ადმინისტრაციასთან დაკავშირებას ითხოვს. წყაროდან შემოტანილი ვაკანსიის ფასიანი განთავსება არსებული `approvePlacement`-ით მხარდაჭერილი არ არის და UI-შიც გამორთულია. გაუქმებული გამოუყენებელი ინვოისის მქონე ვაკანსიის უფასოდ აღდგენა შესაძლებელია; გადახდა ხელახლა არ გამოიყენება.

## 2. ანგარიშსწორების ხედი

ანგარიშის მფლობელის ნავიგაციაში დამატებულია „ანგარიშსწორება“. API ინვოისებს აბრუნებს მხოლოდ სესიის კომპანიის `company_job_ownership`-ით. ჩანს ყველა ინვოისი, თანხა, მომსახურება, სტატუსი, თარიღი და მიმდინარე რეკვიზიტები. ნახვა/PDF იყენებს არსებულ `/invoices/[token]` გვერდსა და მის „ბეჭდვა / PDF“ ქმედებას. ცალკე PDF ფორმატი არ შექმნილა. ძველი ინვოისის გადახდისთვის მომხმარებელს კონკრეტულ ინვოისზე შენახული რეკვიზიტების გამოყენება ეთხოვება.

## 3. პაკეტები და ბალანსი — არ დამატებულა

არსებული ბილინგი არის კონკრეტულ ვაკანსიაზე მიბმული ფიქსირებული ინვოისი. პაკეტის რაოდენობის, კომპანიის ბალანსის, კრედიტების დარიცხვის/ჩამოჭრისა და მათი დაბრუნების რეესტრი არ არსებობს. `approvePlacement` ამოწმებს კონკრეტული საფეხურის ფასსა და ვადას. ამ პირობებში მრავალგანცხადებიანი შეკვეთა მხოლოდ კონფიგურაციის დამატებით ვერ იმუშავებს: საჭიროა ახალი საბუღალტრო ლოგიკა და ფასების გადაწყვეტილება. მოთხოვნის პირობის შესაბამისად გაყიდვა/ფასები/ფასდაკლება არ დამატებულა, არც მოქმედი უფასო კომპანიის ფუნქციები გამხდარა ფასიანი.
