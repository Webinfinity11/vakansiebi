# ადმინ პანელის (/admin) UX მიმოხილვა

თარიღი: 2026-09-21. მეთოდი: მხოლოდ კოდის წაკითხვა (`app/admin/panel.tsx`, `reports.tsx`, `scraper-limits.tsx`, `scraper-metrics.tsx`, `invoice-email-test.tsx`, `billing-settings.tsx`, `attention-board.tsx`, `login.tsx`, `lib/admin-attention.ts`, შესაბამისი `app/api/admin/*` და `admin.css`). **რეალურ ფლოუებში ადმინად შესვლა ვერ მოხერხდა** — `.env`-ში მხოლოდ `ADMIN_PASSWORD_HASH` არის, plaintext პაროლი არსად მოიძებნა, და მისი გამოცნობა/მოძებნა არ ვცადე. ქვემოთ ყველა დაკვირვება კოდიდან გამომდინარეობს, არა ცოცხალი გამოყენებიდან.

## ტოპ-3 ყველაზე ღირებული

1. **შეტყობინების ვაკანსიაზე პირდაპირი გადასვლა არ არსებობს** — `reports.tsx`-ში ერთადერთი ბმული საჯარო გვერდზეა; რეალურად რაიმეს შესასწორებლად ადმინი ხელით უნდა გადავიდეს „ვაკანსიები“-ში და სათაურით მოძებნოს იგივე ჩანაწერი. იგივე ნიმუში (`onReview(id)`) უკვე მუშაობს ინვოისებზე — მისი გამეორება რეპორტებზე იაფია და დღიური სამუშაოს ციკლს პირდაპირ ამოკლებს.
2. **„შემოტანის ისტორია“ არასწორი მიმართულებაა** — `lib/admin-attention.ts:119`-ის რჩევა უგზავნის ადმინს run-log-ს, სადაც დადასტურება/უარყოფა საერთოდ არ არსებობს; ფაქტობრივად საჭირო მოქმედება „ვაკანსიები“ → „შესამოწმებელი“ ფილტრშია. ეს რეალურად შეცდომაში შემყვანი ტექსტია, არა მხოლოდ მოსახერხებლობის საკითხი.
3. **დადასტურების შემდეგ რიგი არ გრძელდება** — ყოველი მოქმედების (`save`/`publish`/`reject`/`archive`) შემდეგ `panel.tsx:332` ხურავს Sheet-ს მთლიანად; ყოველი მომდევნო ჩანაწერისთვის ადმინმა ხელახლა უნდა გახსნას სია და დააჭიროს შემდეგს. ეს ყველაზე ხშირი მოქმედებაა პანელში მთლიანად.
