## დამატებითი release QA

Chrome CDP-ის `Profiler.startPreciseCoverage({callCount:true,detailed:true})`-ით დაითვალა ნამდვილი production `JobCard` ფუნქციის გამოძახებები. რენდერში დიაგნოსტიკური კოდი არ დამატებულა. აკრეფის შემოწმებაში ახალი API პასუხი დროებით შეჩერებულია, რათა ძველი 120 ბარათის რენდერი ახალი შედეგების კანონიერ რენდერში არ აგვერიოს.

- **120 ბარათზე „მენეჯერი“-ს აკრეფა: 0 `JobCard` გამოძახება.** მობილურ sheet-ში ქალაქის/კატეგორიის draft-ის ცვლილება: **0**; draft მოთხოვნები=0, `aria-busy=false`. `memo`, `toggleSave`, `openJob`, `hideJob` უკვე სტაბილური იყო — callbacks-ის დამატებითი ცვლილება საჭირო არ გახდა.
- **„მეტის ჩვენება“ ×5**: 20→40→60→80→100→120. ხუთივე ღილაკის handler გამოიძახა DOM click-მა, ავტომატური pagination-ის ჩარევის გარეშე; ჩვეულებრივი ღილაკის კლიკი/ავტომატური დამატება ცალკე UI სცენარითაც შემოწმებულია. ყოველი დამატება ზუსტად 20 ახალ `JobCard` გამოძახებას იწვევდა. დროები **295 / 304 / 325 / 332 / 346ms**, DOM ელემენტები **1,808 / 2,547 / 3,310 / 4,018 / 4,743**. დაკვირვების მონაკვეთში ≥50ms long task არ დაფიქსირდა; ბოლოს JS heap≈20.1MB. ეს desktop/CPU1× დაკვირვებაა, არა სუსტი ტელეფონის მეხსიერების გარანტია. ვირტუალიზაცია არ დამატებულა.
